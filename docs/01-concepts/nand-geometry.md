# NAND 组织与容量

NAND（NOT AND，非与型闪存）几何描述介质内部的寻址和擦写单位，连接拓扑描述主控如何访问这些介质。初始化参数需要同时匹配两者。

## 1. 连接拓扑与内部结构

主控通过通道和片选访问 NAND 封装。通道是板级总线，一个封装可以包含多个 die，并可能提供多个片选。封装数量、片选数量和 die 数量之间没有固定的一一对应关系。

```text
连接拓扑（板级总线与目标选择）
SSD 主控
 ├─ 通道 CH0 ────────────── CH = Channel，独立 NAND 总线，可跨通道并行
 │   ├─ 片选 CE0 ────────── CE = Chip Enable，选择该通道上的 NAND 目标
 │   │   └─ LUN / die ───── LUN = Logical Unit Number，逻辑单元号；die 为晶粒
 │   └─ 片选 CE2 ────────── 同一通道上的另一个目标
 ├─ 通道 channel（CH1）
 └─ ...

介质内部结构（封装与擦写单位）
NAND 封装 package ───────── 焊接在板上的物理封装，可含多个 die
 └─ 晶粒 die ────────────── 可独立执行操作的晶粒
     └─ 平面 plane ──────── die 内的并行单元，示例为每 die 4 个
         └─ 块 block ────── 擦除单位
             └─ 页 page ─── 常见的读取和编程单位
                 ├─ 主数据 ─ 例如 16 KiB
                 │   └─ sector ─ 此处指 512 B 传输单位，一页主数据包含 32 个
                 └─ OOB ──── Out-of-Band，页备用区
                             用于 ECC（Error Correction Code，纠错码）、标记与元数据
```

通道和片选不属于封装内部的层级；一个封装可连接多个片选或接口。LUN 与 die 的对应关系按 NAND 规格解释。

以本次 SM2263XT + YMTC 示例配置为例，一个块有 2304 页，每页主数据为 16 KiB：

```text
block
 ├─ page 0       16 KiB 主数据 + OOB
 ├─ page 1       16 KiB 主数据 + OOB
 ├─ ...
 └─ page 2303    16 KiB 主数据 + OOB

一页主数据 = 16 KiB = 32 × 512 B
一块主数据 = 2304 × 16 KiB = 36 MiB（不含 OOB）
```

页编程受编程次数、页序和单元类型约束。覆盖已编程数据通常需要先搬移有效数据，再擦除所在块。FTL（Flash Translation Layer，闪存转换层）和 GC（Garbage Collection，垃圾回收）负责将这些约束转换为主机可用的逻辑块访问。

主机的逻辑块大小由 namespace 的格式决定，常见为 512 B 或 4 KiB。厂商命令中的 512 B 传输单位应与主机逻辑块区分。

## 2. 几何与拓扑示例：SM2263XT + YMTC NAND

本次项目使用的示例板焊有两个 NAND 封装，表面丝印记录为 `KRN09TC1B1JD2C`。工具选中的 Flash.SET 配置行标识为 `YMN09TC1B1OC6C / 8Tbit / 2Die`；配置行名称与封装丝印属于不同来源，不能直接互换。

| 项目 | 示例值 |
| --- | --- |
| 通道 | 4，CH0..CH3 |
| 每通道有效片选位置 | CE0、CE2 |
| 每个有效片选位置的 die 数 | 2 |
| 总 die 数 | 4 × 2 × 2 = 16 |
| 主数据页大小 | 16 KiB |
| 每页 512 B 单位数 | 32，对应此配置的 P+0x43 |
| 块内页数 | 2304 |
| 参数表中的块数 | 495，对应 P+0x32 |

这些值属于该配置，其他 NAND 的页数、plane 组织、寻址范围和参数编码需要按对应规格解释。

## 3. 容量计算

原始容量由可寻址介质几何决定。主机可用容量还受系统区、坏块、替换空间、静态 SLC（Single-Level Cell，每单元存储 1 bit） 区以及目标容量设置影响。固件可以按整组块分配空间，再对外暴露指定数量的逻辑块。

示例配置采用以下数值：

```text
每个 FBlock 的 512 B 单位数 = 4,712,448
数据 FBlock 数              = 398
对应分配空间                = 1,875,554,304 个 512 B 单位
实际暴露的逻辑块数          = 1,875,385,008（逻辑块大小 512 B）
用户容量                    = 960,197,124,096 B
```

两者满足 `ceil(1,875,385,008 / 4,712,448) = 398`。分配空间与暴露容量的差额来自按 FBlock 取整，不能直接当作全部预留空间。

该示例容量约为 960.2 GB 或 894.25 GiB。GB 与 GiB 的显示差异来自进制换算；目标容量和预留策略造成的容量变化需要单独计算。

## 4. 页主数据与 OOB

每个 NAND 页包含主数据区和 OOB（spare）区。OOB 可用于 ECC、坏块标记和内部元数据，具体分配取决于 NAND 和控制器。

ECC（Error Correction Code，纠错码）的纠错能力与编码方案、码字长度及校验字节数有关。物理 OOB 空间与用于坏块替换、垃圾回收的预留容量 OP（Over-Provisioning）是不同概念。

## 5. FBlock

FBlock（Firmware Block）是固件使用的块组织单位，可能聚合多个物理块，其组成规则属于控制器实现。容量分配和地址替换必须使用同一套几何解释。

示例配置的 `sectors_per_fblock = 4,712,448`，对应 `2,412,773,376 B`。该数值不能作为其他配置的默认值。

## 6. 坏块与时序

出厂坏块通常通过指定页或 OOB 的标记识别；增长坏块由后续擦写测试或运行时错误发现。扫描页、标记位置和测试方式依赖 NAND 配置，见 [坏块与地址重映射](bad-block-and-remap.md)。

NAND 接口配置包括频率、读写时序、驱动强度及训练参数。Flash.SET 等数据库用于选择这些参数。错误配置可能导致识别、训练或擦写失败；具体故障原因需要结合状态和对照结果确认。
