# 主控的三种运行状态：ROM / MPISP / ISP

SM2263XT 的初始化涉及 ROM（Read-Only Memory，只读存储器）、MPISP 和 ISP 三种运行状态。本文说明各状态的职责、识别方法和迁移条件。

## 1. 启动与维护阶段的职责

主控上电时，NAND（NOT AND，非与型闪存） 可能为空或包含无效固件。片内 ROM 不依赖 NAND 中的工作固件，提供基础识别和程序接收能力，作为后续加载维护程序的入口。

```text
ROM  ──上传维护程序──►  MPISP  ──写固件+复位──►  ISP
 │                        │                       │
 │ 片内固化代码          │ 在 SRAM 执行，掉电丢失    │ 从 NAND 加载，长期存在
 └─ 能力最小               └─ 执行维护操作           └─ 对外提供 NVMe
```

## 2. 工厂模式选择点 P13

项目示例板通过 `JV1` 连接 P13 与 GND（Ground，地）：

```text
P13 = 0（短接）  → 强制 ROM
P13 = 1（悬空）  → 正常启动流程
```

**它在上电时被采样。** 所以：

- 要进 ROM：先短接，再上电；
- 要正常启动：先拆短接，再断电、重新上电。

保持短接状态按复位键/发 `C0/01`，CPU（Central Processing Unit，中央处理器） 仍然会回到 ROM。

## 3. 运行状态识别

运行状态通过设备返回信息识别。`C2/87` 的 1024 B 响应包含以下字段：

```text
byte 0x210 == 1  且 0x211 起前缀 "MPISP"   → MPISP
byte 0x210 == 2  且 0x211 起前缀 "ISP"     → ISP（工作固件已启动）
其他                                        → ROM
```

本工具里对应：

```sh
sudo ossd read mode
# DriveInfo raw mode byte: 00
# DriveInfo mode label: SM2263AA...
# Run mode: ROM
```

**注意**：`Identify` 返回的 `SM2263 / 2777` 不能用来判断模式——ROM 和 ISP 都可能
报同样的型号字符串。另外，ROM 状态下磁盘容量会显示成一个约 1.1 GB 的占位值，
这是 ROM 的典型特征，不代表真实容量。

## 4. 各运行状态的命令能力

| 能力 | ROM | MPISP | ISP |
| --- | --- | --- | --- |
| Identify / 读厂商信息 | ✅ | ✅ | ✅ |
| 读 Flash ID（C2/40） | ✅ | ✅ | ❌ |
| 上传 MPISP（C1/80） | ✅ | — | ❌ |
| 下发参数（C1/90） | ❌ | ✅ | ❌ |
| 扫描/擦除 NAND | ❌ | ✅ | ❌ |
| 读写系统块（C0/03、C1/83） | ❌ | ✅ | ❌ |
| 暴露 namespace、正常读写 | ❌ | ❌ | ✅ |
| 厂商 C0/C1/C2 命令 | 按子命令支持 | 按子命令支持 | 按子命令支持，已验证模式查询 |

初始化主路径为：**ROM 接收程序 → MPISP 执行介质配置与写入 → 复位 → ISP 验收**。表中维护操作以对应 MPISP 实现为准，不能据此推定所有 ISP 厂商命令均不可用。

## 5. 状态迁移图

```text
        ┌──────────────┐
        │     ROM      │◄──────────┐
        └──────┬───────┘           │
               │ 上传 MPISP         │ C0/01 复位
               ▼                   │（短接仍在）
        ┌──────────────┐           │
        │    MPISP     │───────────┘
        └──────┬───────┘
               │ 写 InfoBlock/MPInfo 后复位，
               │ 并拆掉 P13、重新上电
               ▼
        ┌──────────────┐
        │     ISP      │  固件从 NAND 读 InfoBlock 并启动
        └──────────────┘
```

## 6. 状态判定边界

- **Identify 响应**：ROM 也可响应，需结合运行模式和容量判断启动结果。
- **复位条件**：工厂短接保持接通时，复位后仍可能进入 ROM；正常冷启动测试需解除短接。
- **占位容量**：ROM 路径观察到的约 1.1 GB 不代表真实用户容量。
- **CheckISP 失败**：短接可能使模式检查失败；需解除短接后冷启动，并核对模式、身份、容量和读写结果。

相关命令与响应字段见 [协议交互参考](protocol.md)。
