# 故障排查

本文按连接、运行模式、写入比较和启动现象组织排查步骤。表内固定容量及参数值属于 SM2263XT AD + YMTC 8Tbit 项目示例，其他配置需使用对应预期值。

## 1. USB 设备连接失败

```text
open 152d:0583: no matching USB target
```

| 先确认 | 做法 |
| --- | --- |
| USB（Universal Serial Bus，通用串行总线） 桥枚举状态 | `ioreg -p IOUSB -l | grep -i jms`、`lsusb` |
| 权限 | macOS 用 `sudo`；Linux 加 udev 规则 |
| USB 口 | 使用主机直连端口，避免无源 hub |
| 桥接芯片无响应 | `sudo ossd dev usbreset` 再试 |

## 2. USB 连接成功但 Identify 失败

```text
identify: failed (reason=12, fault=6)
```

该结果表示命令未取得有效响应，需要结合 USB 传输状态和主控运行状态定位原因。

| 可能 | 判断 | 处理 |
| --- | --- | --- |
| 当前子命令与工作固件不兼容 | 标准存储访问正常，但指定厂商命令失败 | 核对运行模式及该子命令的支持范围 |
| 主控处于异常状态 | 系统里没有盘，也没有 1.1 GB 设备 | 断电重上电（先接回短接） |
| 桥的传输阻塞 | 所有命令都超时 | 尝试 `dev usbreset`，恢复失败时完整断电 |

## 3. 运行模式读取失败或未进入 MPISP

```sh
sudo ossd read mode
```

```text
Run mode: ROM        → 尚未上传 MPISP，或程序未成功启动
Run mode: MPISP      → 已进入维护模式
读取失败             → 见第 2 条
```

上传后如果不是 MPISP：

- 换 USB 口（供电不足最常见）；
- 确认没有其他程序占用设备；
- 重新执行 `mpisp upload`。

## 4. C1/90 回读不匹配

```text
readback P[0:256]: mismatch
```

| 原因 | 处理 |
| --- | --- |
| P 生成错（拓扑/几何） | 检查 `param build` 打印的 `ce=8`、`P43=32` |
| 用了未配置的 D 模板 | 确认 `D6C=07`、`P7E=90` |
| 通道被其他进程占用 | 关闭 MPTool / 磁盘工具 |

## 5. Save Compare 不匹配

```text
compare: host=0x... device0=0x... device1=0x...: mismatch
```

按主机与两个副本的比较结果定位差异：

- 仅 device1 不同：检查第二副本的地址、写入状态与读回数据。
- 两个设备值相同但与主机不同：检查页选择、数据范围、读写模式与累加规则。
- 三个值均不同：分别核对参数、镜像与两个副本的实际内容。

**历史问题**：`P+0x1A` 没写（=0）时，写到第 64 页之后内容会被污染，表现为
前 64 页读回一致，后续页异常。确认 `P1A=06`。

## 6. 系统区写入后冷启动未枚举

按以下顺序记录启动条件与枚举状态：

1. 确认 P13 工厂短接已解除，避免强制进入 ROM（Read-Only Memory，只读存储器）。
2. 完整断电后重新上电，区分冷启动与 CPU（Central Processing Unit，中央处理器） 复位结果。
3. 分别查询 USB 桥、PCIe（Peripheral Component Interconnect Express，高速串行扩展总线） 端点、运行模式和 namespace，定位失败层级。占位容量可辅助判断 ROM 状态；无磁盘节点不能单独证明主控未启动。
4. 使用其他主机或连接路径对照，区分桥接、主机枚举与控制器问题。

固件输入与系统区的示例检查项如下：

| 检查项 | 期望 |
| --- | --- |
| `D00` | `0x90`（不是 0x45） |
| `P+D0/D1` | `0x07 / 0x01`（不是 0/0） |
| InfoBlock 页数 / descriptor | 与输入自洽，checksum 通过 |
| BootISP 选择 | ROM 标签 `SVN02777` → A3 |
| core0 修订 | 与 BootISP 配对（A3↔A3） |
| ISP 包长度 | 1,179,648 字节 |

## 7. 状态解释与恢复条件

### ROM 占位容量

示例设备在 ROM 路径可能报告约 1.1 GB。该值不代表用户容量，需结合运行模式查询确认。正常启动测试应解除工厂短接并完整断电重启。

### 用户容量与分配空间

示例设备的目标容量为 960,197,124,096 B。系统区、预留空间和坏块替换影响容量分配，FBlock 取整还会造成分配空间与暴露容量的差额，见 [NAND 组织与容量](../../../01-concepts/nand-geometry.md)。

### CheckISP 失败

CheckISP 失败表示该次运行模式检查未满足条件。工厂短接、传输失败或实际启动异常均需分别核对，不能单凭该错误认定介质损坏。

### 维护入口与重新初始化

ROM 提供本流程的维护程序上传入口。硬件正常且入口可访问时，可重新上传 MPISP 并执行初始化。短接方式按板级设计确认，不将示例板接线作为所有板卡的要求。

### 数据保留

初始化会擦写系统区并重建映射。需要保留的数据应先备份，不能依赖初始化后的恢复。

### 不同 NAND 的适配

主流程可以复用，Flash.SET 行、拓扑、时序及容量需要按 NAND（NOT AND，非与型闪存） 配置派生；BootISP 与 core0 按主控修订配对。适配方法见 [NAND 型号适配流程](../../../05-reference/adding-a-nand.md)。
