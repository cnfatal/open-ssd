# SaveInfoBlock：页计划、spare 与校验

## 1. 写入目标与范围

```text
副本 0  → P20
副本 1  → P21
索引    → P23（IdxBlock，最后单独写）
```

每个副本写 `L = P[48h]` 页（项目示例设备 768 页），每页 16 KiB。
InfoBlock 有效内容 `K` 页（项目示例设备 101 或 104），`K..L` 用 `0xFF` 填充
（原实现对这部分没有定义值，是显式选择）。

## 2. 命令与模式

```text
擦除      C0/03  mode=84h   CDW13 = block 低 16 位
写页      C1/83  mode=95h（前 4 页）/ C5h（其余）
           CDW10 = (P43+1) × 128 = 33 × 128 = 0x1080
           CDW13 = (page << 16) | block
```

**84h 只用于擦除，不能拿去当写页模式。** 早期曾把两者混用，导致页数据全错。

IdxBlock 的写页固定用 `C5h`。

## 3. 每页 spare（512 B）

主数据 16 KiB 之后跟 512 B spare，结构：

```text
+00      E1h            系统页标签
+01      typeMap[page]  该页类型
+02      页号低字节
+10      E1h            第二平面标记（plane*32 + 0x10）
其余     0
```

IdxBlock 的 spare 不同：

```text
12 × FFh, 5A AA 5A AA, E5h, 25h
```

typeMap 只有 `K` 字节有效；`K..L` 的取值原实现未定义，本工具填 `FFh`。
（原实现会读到 105 之后，属于越界读，不能当有效数据。）

## 4. 校验

```text
主机：对最终 InfoBlock 缓冲区做 32-bit 字节累加（sum32，覆盖 sector_count × 512）
设备：C2/8D82 返回首 4 字节 LE32
比较：host == device0 == device1
```

注意：**Compare 不是对 768 个物理页全部累加**，而是按 `K` 页内容。
所以两边都算出相同值不代表 768 页每一页都对。

## 5. 实测结果

```text
104 页版本：host=0x0605BE33 device0=0x0605BE33 device1=0x0605BE33  match
101 页版本：host=0x05E63044 device0=0x05E63044 device1=0x05E63044  match
```

两个版本都能通过校验，因为校验只覆盖各自的有效页。

## 6. P+0x1A 错误导致的页数据异常

`P[0x1A]` 是页高字节（项目示例设备 = 6）。如果它是 0：

```text
page 0..63   正常
page 64+     数据被污染
768 页写入后校验 mismatch
```

这个 bug 曾经让整轮 Save 失败，表现是"前 64 页读回一致，后续页异常"。
任何从存档夹具复用 P 的场合，都要先核对 `P1A`。

## 7. 失败与清理

```text
擦除失败        → 停止，不再写
写页失败        → 停止，两个副本状态可能不一致
Compare 失败    → 报告两个 device 值，不自动重写
```

原实现里 copy0 失败不会自动回滚 copy1；重试需要从擦除开始。
