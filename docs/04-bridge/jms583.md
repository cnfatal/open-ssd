# JMS583 USB–NVMe 桥接协议

JMS583 将 USB（Universal Serial Bus，通用串行总线） 存储请求转换为下游 NVMe（Non-Volatile Memory Express，非易失性存储接口规范） 请求。本文说明其传输封装、复位语义和已观察到的状态报告偏差。

## 1. 桥接芯片职责

M.2 插槽是 PCIe（Peripheral Component Interconnect Express，高速串行扩展总线） 接口，USB 口是 USB 接口，两者协议完全不同。桥接芯片
（JMS583）的数据路径如下：

```text
USB 主机 ──► USB 设备控制器 ──► NVMe 主机控制器 ──► M.2 上的 SSD
            （USB 大容量存储设备）   （下游 NVMe 主机）
```

JMS583 在主机侧呈现为 USB 大容量存储设备，在 SSD（Solid-State Drive，固态硬盘）侧作为 NVMe 主机。
桥接芯片负责协议转换和命令转发，NAND（NOT AND，非与型闪存） 访问与 FTL（Flash Translation Layer，闪存转换层） 由 SSD 主控负责。

## 2. USB 侧：BOT 三阶段

最常用的传输方式是 BOT（Bulk-Only Transport），一条命令分三步：

```text
① CBW  —— 主机发 31 字节命令块（读/写、LBA、长度）
② DATA —— 数据阶段（读：设备→主机；写：主机→设备）
③ CSW  —— 设备回 13 字节状态（成功/失败 + residue）
```

USB 侧是单队列串行的：当前命令的 CSW（Command Status Wrapper，命令状态封装） 返回前，不提交下一条命令。所以开卡时
大量小命令的耗时主要花在往返延迟上。

## 3. NVMe 侧：标准命令与厂商命令

桥支持两类：

| 类型 | 用途 | 触发方式 |
| --- | --- | --- |
| 标准 NVMe | 工作固件启动后的 Identify / Read / Write | 普通 SCSI 读写，桥翻译 |
| 厂商透传 | 开卡阶段的 C0/C1/C2 命令 | 特殊 SCSI 命令（A1）携带原始 64 B SQE（Submission Queue Entry，提交队列项） |

开卡用的都是第二类。一条厂商命令的封装大致是：

```text
A1 80  <opcode>  →  准备一条命令（无数据）
A1 83  <payload> →  带数据发送
A1 81            →  执行（无数据）
A1 8F            →  取结果/完成
```

这一层的具体字段见 [协议交互参考](../02-controller/sm2263xt/protocol.md)。
`ossd pretest ...` 对这些序列提供封装。

## 4. 两种复位

```text
USB 复位（ossd dev usbreset）  → 只复位桥，主机重新枚举；SSD 主控不受影响
主控复位（ossd dev reset）     → C0/01，主控 CPU 重启；桥不断开
断电                          → 两者都复位
```

初始化流程通过 `dev reset` 请求主控复位；启动路径受工厂模式选择点等条件影响。`usbreset` 用于 USB 传输恢复，不能保证解除下游主控故障。

## 5. 已知偏差：CSW residue

`CSW.dCSWDataResidue` 表示"还剩多少字节没传"。规范允许在少传/多传时给出非零值，
但已观察到 JMS583 在部分场景中报告值与实际传输不一致，属于该桥接芯片的已知偏差，不是协议本身的规则。

### 5.1 写方向（OUT）

```text
现象：CSW.residue = 完整长度，但 NVMe 状态 = 0（成功）
含义：下游命令状态成功，但桥报告整段数据均未传输；需结合实际传输和读回结果判定
```

仅依据该非零 residue 判定会将部分已完成写操作误判为失败。本工具的处理：

```text
JMS583  → out_residue_quirk 默认开启：写方向满长 residue 视为成功
其他桥  → 默认关闭
```

这是**按桥型号给的默认值**，不暴露成用户参数——否则同一份脚本在不同桥上
行为会不一致。判断成功仍以 NVMe 状态码为准，residue 只作为诊断信息打印。

实现：`ossd/transport/codec.py`、`ossd/transport/bot.py`。

### 5.2 读方向（IN）

读方向也可能出现"residue = 请求长度"但数据完整。工具校验实际收到的字节数，
并在写操作类命令里同时检查 NVMe status。

### 5.3 结论

```text
residue 不是可信的成功判据；
它只是桥的一个实现细节，用来辅助诊断。
```

## 6. 传输性能限制

- 大量小命令：BOT 单队列，延迟受限；
- 超大传输：某些桥会分片，本流程采用 16 KiB 分包传输；
- 桥固件版本不同：residue 行为可能有差异，换桥要重新核对。
