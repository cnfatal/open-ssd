# 桥接芯片系列

桥是主机和 SSD（Solid-State Drive，固态硬盘） 之间的翻译层。不同桥的封装格式、状态语义不一样，
所以按型号分页；工具里也按桥选默认策略。

## 1. 桥接芯片职责

```text
USB 主机 ── BOT ──► 桥 ── PCIe/NVMe ──► SSD
```

桥接芯片负责协议转换，NAND（NOT AND，非与型闪存） 访问和 FTL（Flash Translation Layer，闪存转换层） 由 SSD 主控负责。桥接实现影响以下接口行为：

```text
- 厂商命令封装方式（A1 子命令序列）
- 数据长度字段有多宽（JMS583 是 24 位）
- CSW residue 的行为（影响成功判定）
- 复位是复位桥还是复位主控
```

细节见 [jms583.md](jms583.md)。

## 2. 支持矩阵

| 桥 | 状态 | 说明 |
| --- | --- | --- |
| JMS583 | ✅ 实机验证 | `152d:0583`，本仓库默认桥 |
| 其他 JMicron | ⚠️ 未知 | 封装可能相同，residue 行为需重测 |
| ASMedia / Realtek | ❌ 不支持 | 没有 A1 厂商透传的实现 |

## 3. 桥接芯片适配条件

```text
1. 是否支持厂商命令直通（能发任意 64 字节 SQE）
2. 写方向的 CSW residue 是否可信
3. 单次传输上限
4. 复位语义：C0/01 是否只重启主控
```

第 2 条最容易被忽略：JMS583 在写方向会报"全长未传"但实际成功，
如果按规范严格判断，所有写操作都会被误判为失败。

## 4. 桥接芯片扩展流程

```text
1. 用抓包确认封装（CBW/CSW + 厂商命令的 CDB）
2. 记录一条已知命令的请求/响应字节
3. 写清 residue 行为与最大长度
4. 在这里加一页，并在工具里给出该桥的默认策略
```

不要假设"都是 USB（Universal Serial Bus，通用串行总线） 桥所以一样"——residue 和长度字段的差异会直接导致写失败。

## 5. 工具集成

桥的默认策略写在代码里，不是用户参数：

```text
jms583_transport_config()  → out_residue_quirk = 1
其他桥                     → 0
```

桥型号对应的传输策略由适配层统一选择。
